# UI presentation lock approval sheet

## Owner preferences
- Primary presentation: compact / icon-first
- Permanent explanatory text: forbidden unless essential or specifically approved
- Notes, tutorials and parameter explanations: contextual `?` help
- Primary actions: distinct controls, clear affordances
- Exception register: record which visible text is indispensable for comprehension/accessibility

## Approval checklist
- [ ] Every distinct command has a clear reachable control, not a false combined action
- [ ] Contextual help is behind `?`, usable on touch, keyboard and mouse
- [ ] Input labels/errors/statuses are still discoverable and accessible
- [ ] Each control specifies inputs, outputs, validations, error states and undo
- [ ] Actual interactive prototype shows real behavior, not dead buttons
- [ ] Owner reviewed density, icon meaning, placement and mobile/desktop variants
- [ ] Implementation matches locked inventory and approved exceptions
