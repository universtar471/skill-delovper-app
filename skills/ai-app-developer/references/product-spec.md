# Requirements and MVP specification

Define the user persona and explicit job-to-be-done. Group features as P0 (required for one usable end-to-end journey), P1 (next) and P2 (later). Document exclusions.

Each feature must have: ID, business reason, entry screen/action, inputs and validation, normal path, empty/loading/error/offline states, permissions, data retention, output, acceptance tests. Track platform parity or deviations.

Deliverables: brief, numbered feature spec, user journey, screen map, data entities, API boundary, nonfunctional requirements (security, accessibility, performance, offline behavior, localization), and milestone backlog.

MVP gate: one core task can be completed without mock buttons; no fake controls, hardcoded user-sensitive data or status-only demos presented as finished apps. Use `assets/templates/feature-spec.md`.
